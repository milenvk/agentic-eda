== The Three Mapping Types

Each chapter maps to the application in one of three ways:

* **Workflow chapter:** introduces or extends a business workflow; new components arrive only
  because that workflow slice needs them.
* **Component chapter:** a new agent, service, or store is the star; workflows advance as a side
  effect.
* **Layer chapter:** a cross-cutting concern (testing, security, observability, cloud) applied
  across the existing system; it owns no new business workflow but touches many.

Every chapter still ends with the working system one increment richer; the type only says what
carries the narrative. Under the immutable-component rule (01_system_overview.adoc, ground
rules) a chapter's code is its compose file: the column "Selected for the first time" lists the
components whose code first runs, complete, in that chapter, and "Switched on" the behaviour
its configuration enables in components already running. Event types debut in the chapter
named in the catalog (02_workflows_and_events.adoc); the fixed points of the spine are the
customer's decision in ch 3, `booking.TripConfirmed` in ch 8 with the customer reference, and
payment offstage until ch 10.
